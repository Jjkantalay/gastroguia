# Гастрогид

Новая версия gastroguia.ru — путеводителя по блюдам Кавказа и соседних кухонь (Турция, Иран, Средняя Азия, Крым): 300 блюд, 21 кухня; описания, история, ингредиенты и аллергены, переводы на английский и испанский, а также ассистент на Claude.

Есть две версии сайта:

- **Next.js** (корень проекта) — с базой данных и ассистентом на Claude;
- **C** (папка [`c/`](c/README.md)) — один небольшой сервер на чистом C без зависимостей, с HTML-шаблонами в том же стиле и 20 языками. Готовая сборка для Windows — `c\bin\gastroguia.exe`, запускается из корня проекта.

## Стек

- **Next.js 16** (App Router, TypeScript, Tailwind CSS 4): сайт и API
- **PostgreSQL 16 + pgvector**: база блюд, полнотекстовый поиск по-русски, колонка под эмбеддинги для семантического поиска; для разработки — встроенный PGlite
- **Drizzle ORM**: схема и миграции
- **Claude API** (`@anthropic-ai/sdk`): ассистент, который ищет ответы по базе через инструменты

## Структура

```
src/
  db/schema.ts        схема БД: dishes, cuisines, ingredients, tags
  db/seed.ts          загрузка content/dishes.json в базу
  lib/dishes.ts       поиск и чтение блюд — общий слой для сайта, API и агента
  lib/agent.ts        ассистент: системный промпт и инструменты
  app/                страницы: /, /dishes, /dishes/[slug], /assistant
  app/api/            REST API: /api/dishes, /api/dishes/[slug], /api/agent
content/dishes.json        контент, перенесённый со старого сайта
content/dishes-extra.json  добавленные блюда (300 всего), новые кухни и названия на других языках
content/photos.json        авторы и лицензии фото блюд
content/i18n.json          интерфейс на 20 языках
content/translations/      полные тексты блюд на 19 языках, по файлу на язык
scripts/              перенос с WordPress и скачивание фото
drizzle/              SQL-миграции
```

## Локальный запуск

Нужны [Node.js 22](https://nodejs.org) и [Git](https://git-scm.com). База данных для разработки встроенная (PGlite — PostgreSQL внутри Node.js, с pgvector), отдельно ставить её не нужно: данные лежат в папке `.pglite`.

```bash
git clone https://github.com/Jjkantalay/gastroguia.git
cd gastroguia
git checkout claude/sleepy-faraday-80szzq
npm install
cp .env.example .env          # в Windows: copy .env.example .env
npm run db:migrate            # создать таблицы
npm run db:seed               # загрузить content/dishes.json (можно запускать повторно)
npm run images:download       # скачать фото блюд, логотип, текстуру, иконки и шрифт со старого сайта
npm run dev                   # открыть http://localhost:3000
```

С папкой `.pglite` одновременно работает только один процесс: перед `db:migrate` или `db:seed` остановите `npm run dev` (Ctrl+C).

Чтобы работать с обычным PostgreSQL (например, `docker compose up -d db`), поменяйте `DATABASE_URL` в `.env` на `postgres://…` — пример есть в `.env.example`.

Для ассистента впишите ключ Claude API в `ANTHROPIC_API_KEY` в файле `.env`. Без ключа сайт работает, а ассистент отвечает, что не настроен.

## Языки

Страница блюда открывается на любом из 20 языков: `/dishes/kubdari?lang=ja`, переключатель — над названием. Для арабского и фарси страница идёт справа налево. Тексты блюд лежат в `content/translations/<язык>.json` и попадают в базу при `npm run db:seed`; подписи интерфейса — в `content/i18n.json`. Если перевода нет, показывается английский текст с пометкой.

## Фото блюд

Для новых блюд фото берутся с Wikimedia Commons, только со свободными лицензиями (CC0, общественное достояние, CC BY, CC BY-SA). Под каждым фото указаны автор и лицензия, общий список — на странице `/photos`.

```bash
npm run photos:fetch                     # все блюда без фото
npm run photos:fetch -- --limit 20       # первые 20
npm run photos:fetch -- --only plov,lagman
npm run photos:fetch -- --dry-run        # только показать, что нашлось
npm run photos:fetch -- --recheck        # заново подобрать фото, помеченные «проверить»
```

Скрипт ищет фото от самого точного источника к менее точному:

1. Wikidata — по английскому, русскому и родному названию (грузинскому, армянскому, азербайджанскому, персидскому, турецкому). Фото берётся, только если элемент действительно еда: по его классу (блюдо, хлеб, суп, сыр, напиток…) или описанию. Так не попадётся, например, музыкальная группа с тем же названием.
2. Википедия — главное фото статьи с точно таким названием, сначала в русской, потом в английской и родной.
3. Поиск файла на Commons. Такие записи в `content/photos.json` помечены `"review": true`, на странице `/photos` они отмечены знаком «?» — их стоит проверить глазами.

Фото меньше 400 пикселей и несвободные файлы (например, загруженные только в Википедию) пропускаются. Файлы сохраняются в `public/images/dishes/`, авторы и лицензии — в `content/photos.json`. После скачивания выполните `npm run db:seed` и закоммитьте обе папки.

## Перенос с WordPress

```bash
npm run import:wordpress -- путь/к/экспорту.xml   # XML → content/dishes.json
npm run images:download                            # фото → public/wp-content/uploads/...
npm run db:seed
```

Берутся записи типа «Блюда» (JetEngine) с описанием. Английские и испанские версии WPML становятся переводами русской записи. Пустые карточки, записи блога и страницы пропускаются: список пропущенного лежит в `skipped` внутри JSON. Тип блюда в WordPress не хранился, он задан вручную в `scripts/wordpress-to-json.ts`.

Старые адреса переадресуются постоянными редиректами: `/bliuda/<слаг>/` → `/dishes/<слаг>`, переименованные карточки (`lobio-2` → `lobio` и т. п.) — по списку `redirects` из JSON, `/kukhnia/<слаг>/` → каталог с фильтром по кухне.

Фото лежат по тем же путям `/wp-content/uploads/...`, что и раньше, поэтому старые ссылки на картинки тоже продолжат работать. Скачайте их до переключения домена и закоммитьте папку `public/wp-content`. Пока фото не скачаны, можно отдавать их со старого сайта: `LEGACY_IMAGE_ORIGIN=https://старый-адрес`.

Сам XML в репозиторий не кладите: в нём email администратора и служебные данные (`*.xml` в `.gitignore`).

## Перенос в WordPress

Блюда можно загрузить и на сайт на WordPress — с тем же шаблоном Elementor «СтраницаБлюда», полями JetEngine и таксономией «Кухня», на всех 20 языках.

```bash
npm run photos:fetch        # необязательно: фото со свободной лицензией
npm run export:wordpress    # → wordpress/gastroguia-ru.xml и gastroguia-<язык>.xml
```

| Файл | Что внутри |
|---|---|
| `gastroguia-ru.xml` | 284 новых блюда на русском, 9 новых кухонь, фото |
| `gastroguia-en.xml`, `-es.xml` | переводы новых блюд и тех старых, у которых на сайте ещё нет этого языка |
| `gastroguia-fr.xml` … `-az.xml` (17 файлов) | переводы всех 300 блюд, включая 16, которые уже были на сайте |

1. Сделайте резервную копию сайта (в Бегет: «Резервное копирование» — файлы и база).
2. WPML → Языки: добавьте нужные языки (кроме русского, английского и испанского, которые уже есть). Языки, которые не нужны, можно не добавлять и их файлы не загружать.
3. Удалите пустые карточки, которые выведет команда (Кубдари, Лагман, Аджапсандали и др.), и очистите корзину — иначе новые записи получат адреса вида `kubdari-2`.
4. Инструменты → Импорт → WordPress → загрузите `gastroguia-ru.xml`. Автора сопоставьте с `admin`, отметьте «Скачать и импортировать файлы вложений» (по ним скачаются фото с Wikimedia Commons). Если сервер обрывает импорт по времени, повторите — уже загруженные записи пропускаются.
5. Тем же способом загрузите файлы нужных языков. Сначала они появятся среди русских блюд с адресами `kubdari-2` — это нормально.
6. Скопируйте `wordpress/gastroguia-after-import.php` в `wp-content/mu-plugins/` и откройте любую страницу админки. Плагин через WPML привяжет каждый перевод к русской записи, вернёт адрес без «-2» (`/ja/bliuda/kubdari/`) и проставит фото. В сообщении будет, сколько сделано, и чего не хватает (например, языка в WPML). Можно держать плагин включённым, пока загружаете языки по одному, — при каждом открытии админки он доделывает новые записи. Когда напишет «Готово», удалите файл.

Плагин WPML Export and Import не нужен, но поля для него в файлах тоже есть (`_wpml_import_*`).

Номер шаблона Elementor и логин автора меняются переменными `WP_TEMPLATE_ID` (по умолчанию 6194) и `WP_AUTHOR`.

## API

| Запрос | Что делает |
|---|---|
| `GET /api/dishes?q=суп` | поиск по тексту (русская морфология) |
| `GET /api/dishes?cuisine=gruzinskaya&course=выпечка` | фильтр по кухне и типу блюда |
| `GET /api/dishes?vegetarian=true&glutenFree=true&maxTimeMin=30&maxCalories=400` | диета, время, калории |
| `GET /api/dishes?with=тыква&without=мясо` | есть или нет ингредиента (параметры можно повторять) |
| `GET /api/dishes/plov` | всё о блюде, включая переводы |
| `POST /api/agent` `{"messages":[{"role":"user","content":"..."}]}` | ответ ассистента |

У ассистента три инструмента: `search_dishes`, `get_dish` и `list_cuisines`. Они вызывают те же функции, что и сайт, поэтому новый инструмент для агента добавляется в `src/lib/agent.ts` поверх `src/lib/dishes.ts`.

## Развёртывание на VPS

```bash
git clone … && cd gastroguia
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" >> .env
echo "ANTHROPIC_API_KEY=sk-ant-..." >> .env
docker compose up -d db
docker compose run --rm migrate   # миграции и стартовые данные
docker compose up -d app          # сайт на 127.0.0.1:3000
```

Снаружи сайт открывается через nginx или Caddy с HTTPS: проксируйте домен на `127.0.0.1:3000`.
